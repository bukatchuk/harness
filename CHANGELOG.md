## [1.12.0] — 2026-10-16

### Добавлено

- `bin/harness doctor --md` — результат таблицей с эмодзи (✅ ⚠️ ❌) и строкой итога. Skill `harness-doctor` запускает `doctor --deep --md` без обрезки вывода и показывает таблицу владельцу в ответе целиком.
- Ход проверки: пока `doctor` работает, в stderr выводится, что проверяется сейчас (`⏳ SSH <сервер>…`); в терминале — одна обновляемая строка. С `--quiet` (проверка на старте сессии) молчит.

### Изменено

- `doctor --deep` запускает запросы к API, проверку origin и входы по SSH параллельно в начале работы и выводит их в прежнем порядке; `bw status` вызывается один раз. Полная проверка — 12 с вместо 122 с на 8 серверах и 6 сервисах.
- Неизвестный ключ `doctor` теперь отклоняется с подсказкой. Проверки — в `bin/harness selfcheck`.

## [1.11.0] — 2026-10-16

### Добавлено

- `bin/harness secrets` — токены включённых интеграций из хранилища Bitwarden или совместимого сервера: владелец выполняет `eval "$(bin/harness secrets)"` перед запуском claude, и токены попадают в окружение без записи на диск и без вывода в терминал. Имя записи в папке хранилища совпадает с именем переменной; `secrets.extra` в `harness.json` добавляет свои. Раньше токены на каждом устройстве вводились вручную. Описание — в `integrations/bitwarden.md`.
- `bin/harness secrets --check` и раздел `doctor` «Хранилище секретов»: установлен ли `bw`, выполнен ли вход, на тот ли сервер, каких токенов нет в окружении — только имена.
- Хук не выдаёт агенту значения из хранилища: `bin/harness secrets` без `--check`, `bw get`, `bw list items`, `bw unlock`, `bw export` отклоняются. Правило — в `rules/secrets.md`; проверки — в `bin/harness selfcheck`.
- `HARNESS_CONF` — путь к `harness.json` для проверок `selfcheck`.
- Пополнение реестра этой установки: новый репозиторий.

## [1.10.0] — 2026-10-16

### Изменено

- `bin/harness docker-clean` по умолчанию убирает только ресурсы своей сессии и остановленные ресурсы без метки сессии: работающие контейнеры соседних сессий больше не пропадают посреди их тестов. `--all` убирает все ресурсы harness — только по слову владельца. Сессию ресурса задаёт метка `harness.session` или суффикс имени compose-проекта `harness-<проект>-<сессия>`; хук на старте сессии выставляет `HARNESS_SESSION`. Правило — в `rules/docker.md`.
- `bin/harness docker-check` требует нулей только по своей сессии, ресурсы других сессий и без метки показывает отдельно; `doctor` предупреждает о них.

## [1.9.0] — 2026-10-16

### Добавлено

- Команды для задач Plane: `bin/harness task create|state|comment|link|show|list`. Проект выбирается по реестру (`--repo`), состояние — по группе (`todo`, `started`, `done`…), текст задачи и комментария — файлом в Markdown или HTML, без пробелов между тегами. Команды листают страницы, ждут при лимите запросов и проверяют текст на AI-атрибуцию. Раньше агент писал вызовы API заново в каждой сессии. Описание — в `integrations/plane.md`.
- Метка `repo:<имя>`: задача про репозиторий в проекте по умолчанию получает её автоматически, `task list --repo` показывает задачи репозитория. Правило — в `rules/tasks.md`.
- `bin/harness tasks [--stale N]` — задачи в работе по всем проектам и сколько дней они без движения. Хук на старте сессии называет число задач без движения дольше 7 дней; подсчёт идёт в фоне и старт не замедляет.

### Изменено

## [1.8.0] — 2026-10-15

### Добавлено

- Правило секретов: секрет передаётся команде только через файл или stdin, никогда аргументом вроде `--password=$(cat …)`. Аргумент виден в `ps`, а программа, не знающая опцию (busybox `wget`), печатает её вместе со значением — так пароль попал в журнал сессии и потребовал ротации. Доступность цели с паролем проверяется по данным мониторинга, а не ручным запросом. Правило — в `rules/secrets.md`.

## [1.0.0] — 2026-10-10

Первый публичный релиз под лицензией MIT. Ядро harness отделено от данных владельца, поэтому одна и та же версия работает и как личная установка, и как открытый проект.

### Добавлено

- **Настройки установки в `harness.json`**: владелец (имя и почта для коммитов), язык, подключённые интеграции. Создаются командой `bin/harness init`; её же вызывает скрипт установки.
- **Два языка**: правила, skills и шпаргалки существуют на русском и английском (`i18n/ru`, `i18n/en`), сообщения CLI — тоже. Переключение: `bin/harness lang ru|en`.
- **Скрипт установки** `install.sh`: одна команда скачивает harness, проверяет зависимости и запускает настройку.
- **Удаление из реестра**: skills и команды `repo-remove`, `server-remove`, `service-remove`. Сервер или репозиторий, на который ссылаются связи, удаляется только с явным `--unlink`; клон с несохранённой работой — только с `--force`.
- **Сброс**: skill `harness-reset` и команда `bin/harness reset` очищают реестр репозиториев, серверов и связей. Без `--yes` команда только показывает план.
- **Резервная копия реестра** в `.harness-backup/` перед каждым удалением и сбросом.
- **Публичный релиз**: `bin/harness release-build` собирает открытую версию без данных владельца и проверяет её на утечки — почту, IP-адреса, идентификаторы, токены, ключи, домашние каталоги и всё, что названо в настройках и реестре установки. `bin/harness release-publish` отправляет сборку в публичный репозиторий одним коммитом на релиз. Skill `release-public` ведёт по шагам.
- **Проверка целостности** `bin/harness selfcheck` и сквозной тест `tests/smoke.sh`; CI на Linux и macOS.
- `README.en.md`, `CONTRIBUTING.md`, `SECURITY.md`, шаблоны issue и pull request, лицензия MIT.

### Изменено

- Правила, skills и шпаргалки хранятся в `i18n/`, а `.claude/` — их развёрнутая копия на выбранном языке. Точка входа агента теперь `.claude/CLAUDE.md`. Собственные правила и skills пользователя в `.claude/` при смене языка сохраняются.
- Автор коммитов берётся из `harness.json` и закрепляется в `.claude/settings.local.json`, а не в общем `.claude/settings.json`.
- Интеграции (Plane, n8n, GitGuardian, Yandex Cloud) включаются ключом в `harness.json`; `doctor` проверяет только включённые. Адреса сервисов читаются из настроек.
- `doctor`: отсутствие `gh` и `docker` — предупреждение, а не ошибка; появился раздел «Настройка».
- `bin/harness map` выводит таблицу с именованными столбцами, как `servers` и `status`.
- Отсутствующий файл реестра считается пустым реестром и создаётся автоматически.

### Удалено

- Блок `env` с автором коммитов из `.claude/settings.json`.
