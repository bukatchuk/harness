---
name: service-remove
description: Удалить из реестра harness (registry/services.json) связь между репозиторием и сервером. Использовать, когда владелец говорит, что сервис больше не развёрнут или связь записана ошибочно.
argument-hint: "<сервис>"
---

Удали связь из реестра. Аргументы: $ARGUMENTS

1. Покажи владельцу, что будет удалено: `bin/harness map <сервис>`. Если имя не найдено — покажи все связи (`bin/harness map`) и уточни.
2. Объясни последствие: удаляется только запись в реестре. Сам сервис на сервере и репозиторий остаются как есть; после удаления harness перестанет знать, откуда этот сервис настраивается.
3. **Спроси согласия и дождись ответа.**
4. Удали: `bin/harness service-remove <сервис>`. Команда перед изменением сохраняет копию реестра в `.harness-backup/`.
5. Проверь: `bin/harness map <сервис>` отвечает, что связей нет; `bin/harness doctor` не сообщает о битых ссылках.
6. Если `registry/` отслеживается в git этого harness, это изменение harness: при коммите оно поднимает patch-версию.

Останавливать и удалять сам сервис на сервере — отдельное действие, только по отдельной просьбе владельца и по правилам `.claude/rules/servers.md`.
