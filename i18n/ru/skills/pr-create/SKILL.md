name: pr-create
description: Создать pull request в GitHub или запрос на слияние в GitLab для проекта из repos/ или для harness, без AI-атрибуции. Использовать, когда владелец просит открыть PR или MR.
argument-hint: "[проект] [базовая ветка]"
---

Создай pull request. Аргументы: $ARGUMENTS

1. Определи репозиторий и ветку. Если текущая ветка — основная, сначала создай рабочую: `git -C <путь> switch -c <type>/<кратко-о-сути>`.
2. Проверь коммиты: `bin/harness check-commits <путь>`. При `FAIL` остановись и сообщи.
3. Отправь ветку: `git -C <путь> push -u origin <ветка>`.
4. Собери описание по всем коммитам ветки, а не только по последнему: `git -C <путь> log --oneline <база>..HEAD` и `git -C <путь> diff --stat <база>...HEAD`.
5. Если в проекте есть шаблон (`.github/pull_request_template.md`, `.gitlab/merge_request_templates/`) — следуй ему. Иначе структура такая:
   - **Что и зачем** — 1–3 предложения.
   - **Изменения** — список по существу.
   - **Как проверить** — шаги или команды.
   - Ссылка на задачу в Plane, если она известна.
6. Положи описание в файл и создай запрос там, где живёт репозиторий (`bin/harness forge <путь>`). Никаких «Generated with …» и 🤖.
   - `github` — из каталога репозитория: `gh pr create --base <база> --title "<заголовок>" --body-file <файл>`;
   - `gitlab` — `bin/harness mr <путь> --base <база> --title "<заголовок>" --body-file <файл>`.
7. Верни владельцу ссылку на запрос. Состояние конвейера в GitLab: `bin/harness mr-status <путь> <номер>`.

Слияние — отдельное действие: по просьбе владельца или по правилам проекта, если они разрешают сливать при зелёном конвейере.
