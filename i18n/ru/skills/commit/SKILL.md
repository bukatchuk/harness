---
name: commit
description: Закоммитить изменения в harness или в проекте из repos/ от имени владельца, без AI-атрибуции. Использовать, когда владелец просит сделать коммит.
argument-hint: "[проект] [пояснение к коммиту]"
---

Сделай коммит. Аргументы: $ARGUMENTS

1. Определи репозиторий: проект из `repos/<имя>`, файлы которого менялись, либо сам harness. Если изменения есть в нескольких репозиториях — это отдельные коммиты, по одному на репозиторий; назови владельцу все.
2. Посмотри состояние: `git -C <путь> status --short` и `git -C <путь> diff --stat`. Полный diff читай только по тем файлам, суть изменений в которых тебе неизвестна.
3. Проверь, что в индекс не попадёт лишнее: секреты, `.env`, артефакты сборки, посторонние правки. Нашёл секрет — остановись и сообщи.
4. Если установлен `ggshield` и задан `GITGUARDIAN_TOKEN`, проверь изменения после добавления в индекс: `GITGUARDIAN_API_KEY="$GITGUARDIAN_TOKEN" ggshield secret scan pre-commit` (запускать в каталоге репозитория).
5. Добавь файлы поимённо: `git -C <путь> add <файлы>`.
6. Составь сообщение по `.claude/rules/git.md`: стиль проекта из `git log --oneline -10`, иначе Conventional Commits.
7. Если это harness — до коммита подними `VERSION`, добавь запись в `CHANGELOG.md` и `CHANGELOG.en.md` и включи все три файла в индекс: версию поднимает каждый коммит (см. `.claude/rules/harness.md`).
8. Закоммить: `git -C <путь> commit -m "<заголовок>" -m "<тело>"`. Без `--author`, без `--no-verify`, без трейлеров об AI. Для harness сразу поставь аннотированный тег с описанием на языке владельца: `git tag -a v<версия> -m "<что изменилось>"`.
9. Покажи результат: `git -C <путь> log -1 --format='%h %an <%ae> %s'`.

Push не делай, пока владелец не попросит.
