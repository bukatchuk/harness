name: server-add
description: Добавить сервер в реестр harness (registry/servers.json) с проверкой входа по SSH и сбором сведений о нём. Использовать, когда владелец называет новый сервер или даёт список серверов.
argument-hint: "<user@host[:порт]> [имя]"
---

Добавь сервер в реестр. Аргументы: $ARGUMENTS

1. Разбери адрес: пользователь, хост, порт (по умолчанию 22). Если дан псевдоним из `~/.ssh/config`, узнай настоящие значения: `ssh -G <псевдоним> | grep -E '^(hostname|user|port) '`. Имя по умолчанию — короткое имя хоста; оно должно быть уникальным в реестре.
2. Проверь, знаком ли хост: `ssh-keygen -F <host>` (для нестандартного порта — `ssh-keygen -F '[<host>]:<порт>'`). Если нет — получи отпечаток `ssh-keyscan -p <порт> <host> 2>/dev/null | ssh-keygen -lf -`, покажи его владельцу и дождись подтверждения. Только после этого добавь ключ в `~/.ssh/known_hosts`.
3. Проверь вход: `ssh -o BatchMode=yes -o ConnectTimeout=10 -p <порт> <user>@<host> true`. Не получилось — сообщи причину (ключ, сеть, пользователь) и остановись; пароли не запрашивай.
4. Собери сведения одной командой, только чтение:
   `ssh -o BatchMode=yes -p <порт> <user>@<host> 'hostname; . /etc/os-release && echo "$PRETTY_NAME"; nproc; free -h | sed -n 2p; df -h / | tail -1; command -v docker >/dev/null && docker ps --format "{{.Names}}" | head -30'`
5. Добавь запись в `registry/servers.json` через `jq`, сохранив сортировку по имени. Поля:
   - `name` — короткое имя сервера;
   - `host` — DNS-имя или IP;
   - `port` — порт SSH;
   - `user` — пользователь для входа;
   - `env` — `"prod"`, `"stage"`, `"dev"` или `"lab"`;
   - `provider` — где размещён (Yandex Cloud, Hetzner и т.п.) или `null`;
   - `location` — локация в виде «код страны, город» (например, `NL, Amsterdam`) или `null`;
   - `os` — система, по факту;
   - `description` — одна строка: зачем этот сервер;
   - `notes` — важное для работы или `null`.
6. `os` заполни по факту. Какие репозитории настраивают этот сервер и его сервисы, в запись сервера не пиши — это отдельный реестр связей, skill `service-add`. Чего не знаешь (`env`, `provider`, `location`, назначение) — спроси у владельца, не выдумывай. Секреты, ключи и пароли в реестр не пиши.
7. Проверь результат: `bin/harness server-check <имя>` и покажи итоговую запись.
8. Если `registry/` отслеживается в git этого harness, пополнение реестра — это изменение harness: при коммите оно поднимает patch-версию (см. `.claude/rules/harness.md`).

Несколько серверов сразу добавляй одной правкой реестра. Правила работы на серверах — в `.claude/rules/servers.md`.
