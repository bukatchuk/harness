# Задачи в Plane

Правило действует, если в `harness.json` задан ключ `integrations.plane`. Если его нет — трекер задач не подключён: задачи не заводи и скажи об этом владельцу, когда он попросит.

Адрес Plane, рабочее пространство и проект по умолчанию записаны в `harness.json` (`integrations.plane`: `url`, `workspace`, `default_project`, `default_project_id`). Как обращаться к API — в `.claude/integrations/plane.md`.

## В какой проект заводить

1. Задача про проект из реестра — в его проект Plane: поля `plane_project` и `plane_project_id` в `registry/repos.json`.
2. Задача про сервер или сервис — в проект репозитория, который за него отвечает: `bin/harness map <сервер>`.
3. Во всех остальных случаях, а также если у репозитория проект не указан, — в проект по умолчанию из `harness.json`.

## Статус задачи всегда актуален

Состояние задачи в Plane меняй сам на каждом этапе, не дожидаясь напоминания:

- **Начал работу** — сразу переведи в `In Progress`, до первой команды по задаче. Это касается и задач, которые завёл сам.
- **Сделал часть** — оставь `In Progress` и напиши комментарий: что сделано, что осталось.
- **Сделал всё, что описано в задаче, и проверил результат** — переведи в `Done` и напиши итоговый комментарий с числами «было → стало».
- **Работа остановилась** (ждёшь решения владельца, доступа, внешнего события) — оставь `In Progress` и напиши в комментарии, чего именно ждёшь.
- **Задача не нужна** — `Cancelled` с причиной, только по решению владельца.

Если выполнена только часть задачи, а остальное владелец делать сейчас не просил, не держи задачу открытой молча: спроси, закрывать ли её, а остаток вынеси в отдельную задачу.

В итоговом сообщении владельцу называй текущий статус каждой затронутой задачи.

Идентификаторы состояний у каждого проекта свои: бери их из `/states/` этого проекта по полю `group` (`started` — In Progress, `completed` — Done).

## Как заводить

- Заводи задачу, когда об этом просит владелец или когда работа выявила проблему, которую нужно решать отдельно. Перед созданием проверь, нет ли уже такой задачи.
- В задаче: что обнаружено (с числами), причина, предложенное решение по шагам, риски. Секреты и содержимое `.env` в задачи не пиши.
- После создания верни владельцу идентификатор и ссылку.
- Состояние задач, над которыми работаешь, ведёшь ты (см. выше). Задачи, над которыми ты не работаешь, не трогай; удалять задачи — только по просьбе владельца.
- Если у проекта есть свои правила ведения задач (ветки по номеру задачи, синхронизация с файлом плана) — следуй им.
