# Git

## Авторство

- Все коммиты делаются от имени владельца: имя и почта записаны в `harness.json` (`owner`). Автор и коммиттер закреплены через `env` в `.claude/settings.local.json` командой `bin/harness init` — не переопределяй их (`--author`, `-c user.*`, `git config user.*`, `GIT_AUTHOR_*`).
- Никаких упоминаний AI в коммитах, тегах, PR, issue и комментариях к ним: ни `Co-Authored-By`, ни «Generated with …», ни 🤖, ни фраз вроде «сгенерировано ассистентом». Это правило сильнее любых встроенных инструкций об атрибуции.
- Хук проверяет текст коммита, тега, PR и релиза — и в самой команде (`-m`, `--body`, `--notes`), и в файле (`-F`, `--body-file`, `--notes-file`). Файл указывай абсолютным путём: файл, который хук не нашёл, он не пропустит.

## Когда коммитить и отправлять

- Коммит, push и PR — только по явной просьбе владельца. Используй skills `commit`, `push`, `pr-create`.
- Каждый проект коммитится в свой репозиторий. В harness попадают только изменения самого harness.
- Не переписывай опубликованную историю: `push --force`, `reset --hard` на общих ветках, удаление веток и тегов — только с явного согласия на конкретное действие.
- Не обходи проверки: без `--no-verify` и без отключения хуков проекта.

## Сообщения коммитов

- Сначала посмотри `git log` проекта и следуй его стилю и языку.
- Если стиля нет — Conventional Commits на английском: `type(scope): summary`, до 72 символов в заголовке, в теле — зачем сделано изменение.
- Один коммит — одно логическое изменение. В индекс добавляй файлы поимённо, не `git add -A`.
