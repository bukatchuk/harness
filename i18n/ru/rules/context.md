# Контекст и субагенты

Контекстное окно — главный ограниченный ресурс. Береги его.

## Экономия контекста

- Читай прицельно: сначала поиск (`grep`, `git grep`, `rg`), потом нужный фрагмент файла, а не файл целиком.
- Ограничивай вывод команд: `| head`, `| tail`, `--quiet`, `--oneline`, `jq` с выборкой нужных полей. Логи сборок и тестов — только хвост и ошибки.
- Не загружай заранее то, что может не пригодиться: шпаргалки из `.claude/integrations/`, документацию, соседние проекты.
- Не перечитывай то, что уже есть в контексте.

## Контекст проекта

Новая сессия должна продолжать работу без объяснений владельца. Поэтому контекст проекта живёт в самом репозитории — в `CLAUDE.md` и `.claude/`: решения, текущее состояние, ограничения и прогревочный промпт для начала сессии: короткий блок в `README.md`, который ведёт на снимок состояния (например, `.claude/warmup.md`). Копию снимка в README не держи — тексты разойдутся.

- Владелец пишет «работаем с репозиторием <имя>» (или иначе называет проект, с которым начинаем работу) — первым делом, до любых других действий, прочитай прогревочный промпт в `README.md` этого репозитория и выполни его. Клона нет — сначала `bin/harness sync <имя>`.
- Закрывая каждую задачу (и закончив этап, у которого задачи нет), проверь, что контекст и прогревочный промпт актуальны: текущая версия, что сделано, что в работе, следующий шаг, открытые решения владельца. Устаревшее переписывай, а не дописывай: снимок — короткий «где мы и что дальше», а не журнал.
- Прогревочного промпта нет (нет блока в README или снимка) — заведи недостающее. Правка контекста идёт тем же порядком, что и код проекта (ветка, MR, выкладка).
- В итоговом комментарии к задаче отметь, что контекст проверен или обновлён.

## Субагенты

- По умолчанию работает один агент. Субагент нужен, когда задача независима и объёмна по чтению (обзор кода, поиск по нескольким репозиториям, разбор логов), а в основной контекст должен вернуться только вывод.
- Мелкие задачи на несколько вызовов делай сам: запуск субагента дороже.
- Независимые задачи запускай параллельно, одним сообщением.
- Субагент возвращает сжатый итог: выводы, пути `файл:строка`, что не удалось проверить. Без пересказа прочитанного.

## Модель для субагента

Выбирай самую дешёвую модель, на которой качество не пострадает, и указывай её явно при запуске.

| Задача | Модель |
| --- | --- |
| Поиск, инвентаризация, сбор фактов, разбор логов, механические правки по образцу | `haiku` |
| Реализация по ясной постановке, тесты, ревью обычного кода, документация | `sonnet` |
| Архитектура, запутанная отладка, решения с высокой ценой ошибки, безопасность | модель основной сессии |

Сомневаешься между двумя — бери дешевле и проверь результат сам; если он слабый, перезапусти на модели выше, а не дорабатывай за субагентом вручную.
