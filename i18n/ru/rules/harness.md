# Изменение самого harness

- Каждый коммит в репозиторий harness поднимает версию: в том же коммите увеличь `VERSION` и добавь запись `## [X.Y.Z]` в `CHANGELOG.md` и в `CHANGELOG.en.md`. Исключений нет — git-хуки из `.githooks/` отклонят коммит и push без этого.
- Версия — semver: patch — уточнения, исправления, пополнение реестра; minor — новые правила, skills, интеграции; major — изменения, после которых старое поведение ломается.
- Не правь последний коммит через `--amend` — делай новый коммит с новой версией.
- После коммита ставь аннотированный тег с описанием на языке владельца: `git tag -a v<версия> -m "<что изменилось, 1–3 строки>"`. Тег без описания git-хук не пропустит. Отправляй тег вместе с веткой.
- Для каждого тега создавай релиз в GitHub (это шаг skill `push`). Заголовок — `v<версия> — <суть>`. В описании перечисли все вошедшие изменения функционала по разделам «Добавлено / Изменено / Исправлено / Удалено», и у каждого пункта дай ссылку на md-файл с подробностями по тегу: `<адрес репозитория>/blob/v<версия>/<путь>` — ссылка на тег не устареет. Адрес репозитория: `gh repo view --json url -q .url`.
- Правила, skills и шпаргалки правь только в `i18n/` и сразу на обоих языках: `i18n/ru/…` и `i18n/en/…` должны совпадать по составу файлов и по смыслу. Файлы в `.claude/` — копия, её перезапишет `bin/harness lang`; после правки выполни эту команду. Состав комплектов проверяют `bin/harness selfcheck` и git-хук.
- Тексты, которые видит пользователь CLI, в `bin/harness` пишутся парой: русский и английский вариант рядом.
- В ядре нет данных владельца: имена, адреса, идентификаторы и ссылки живут в `harness.json` и `registry/`. В правилах, skills, шпаргалках, README и коде пиши «владелец» и бери значения из настроек. Запись журнала, которая называет данные владельца, оборачивай в `<!-- private -->` … `<!-- /private -->`: в публичную сборку она не попадёт.
- Публичный релиз собирается из ядра командой `bin/harness release-build` и публикуется только через skill `release-public`. Если в `harness.json` задано `release.auto_publish: true`, публикуй его сам, без напоминания, сразу после каждого успешного релиза приватного репозитория: коммит отправлен, тег и релиз созданы, `bin/harness selfcheck` проходит. Версии публикуются по порядку, без пропусков. Если ключа нет или он `false` — только по просьбе владельца. Сборка нашла утечку — в любом случае остановись и сообщи.
- Держи harness тонким. Прежде чем добавить правило, проверь: нельзя ли решить это скриптом или хуком, и не устарело ли соседнее правило. Правило, которое перестало быть нужным, удаляй.
- Специфику одного проекта не клади в harness — её место в `CLAUDE.md` этого проекта.
- Раз в 15 минут хук проверяет, нет ли в `origin/main` новой версии. Если она есть, предложи владельцу обновиться в текущей сессии. Обновление — только через skill `harness-update` и только с его согласия; после отказа ту же версию повторно не предлагай.
