# Хранилище секретов (Bitwarden или совместимый сервер)

Токены интеграций harness живут в хранилище владельца, а не в файлах и не в git. Хранилище включено, если в
`harness.json` есть `secrets`:

```json
"secrets": {"provider": "bitwarden", "server": "<адрес хранилища>", "folder": "harness", "extra": ["ЕЩЁ_ТОКЕН"]}
```

- В папке `folder` — по записи на токен. Имя записи совпадает с именем переменной (`PLANE_TOKEN`, `GITLAB_TOKEN`, …);
  значение — пароль записи типа «Логин» или текст заметки.
- Какие токены нужны — по включённым интеграциям (`plane`, `n8n`, `gitguardian`, `mailcow`, `gitlab`, `timeweb`, `umami`) и
  списку `extra`.
- Клиент — Bitwarden CLI `bw`. Он держит зашифрованную копию хранилища на устройстве: разблокировка работает и без
  связи с сервером; сервер нужен для входа на новом устройстве и для получения изменений.

## Новое устройство (делает владелец)

```bash
brew install bitwarden-cli          # или npm i -g @bitwarden/cli
bw config server <адрес хранилища>
bw login                             # почта, мастер-пароль, двухэтапная проверка
```

## Каждая сессия (делает владелец, до запуска claude)

```bash
export BW_SESSION="$(bw unlock --raw)"
eval "$(bin/harness secrets)"
claude
```

Удобно завести функцию в профиле оболочки, которая делает то же одной командой. Команда не печатает токены в
терминал и не пишет их на диск: значения попадают только в окружение этой оболочки.

## Что может агент

- `bin/harness secrets --check` — есть ли в хранилище все нужные записи (только имена).
- `bin/harness doctor` — установлен ли `bw`, выполнен ли вход, на тот ли сервер, каких токенов нет в окружении.
- Значения агенту не выдаются: `bin/harness secrets` без `--check`, `bw get`, `bw list items`, `bw unlock`,
  `bw export` хук отклоняет. Не хватает токена — скажи владельцу, какого, и что выполнить.

## Смена токена

Владелец меняет значение записи в хранилище; на каждом устройстве новый токен появится при следующем
`eval "$(bin/harness secrets)"` (команда сначала синхронизирует копию).
